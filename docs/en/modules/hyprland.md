# Hyprland

Configuration is split into:

- shared base: `modules/home/hyprland/hyprland.base.lua`
- host overrides: `hosts/desktop/hyprland.lua` / `hosts/laptop/hyprland.lua`
  (linked by `hosts/<host>/home.nix`)
- Home Manager module: `modules/home/hyprland/default.nix` (Hyprland, rofi, kitty)

The module explicitly selects `configType = "lua"`. It deploys
the shared and host fragments under `$XDG_CONFIG_HOME/hypr` with
`xdg.configFile`; the generated `hyprland.lua` loads them with `require()`.

Related tools:

- [Caelestia](caelestia.md): bar, notifications, launcher, lock and wallpaper
  (`modules/home/caelestia.nix`), including idle handling (hypridle is disabled)
- `hyprlock` (fallback only)
- `rofi`, reduced to the window switcher (`SUPER+W`)
- [Pyprland](#drop-down-terminal-pyprland): drop-down terminal (`modules/home/pyprland.nix`)

## Scrolling layout

Hyprland 0.55 ships the `scrolling` layout natively (windows in horizontally
scrolling columns, no plugin). `dwindle` stays the default layout.

| Shortcut | Action |
|---|---|
| `SUPER + CTRL + S` | toggle the active workspace between `dwindle` and `scrolling` |
| `SUPER + H/L` | previous/next column (scrolls it into view) |
| `SUPER + K/J` | window above/below in the column |
| `SUPER + CTRL + H/J/K/L` | move the window (across columns / within the column) |
| `SUPER + SHIFT + H/L` | resize the column |

The toggle adds a workspace rule at runtime: it is per workspace and is dropped
on `hyprctl reload` (including the GameMode hook's) or when the session
restarts. Tuning (`column_width`, ...) lives in the `scrolling` block of
`hyprland.base.lua`.

## Drop-down terminal (Pyprland)

`SUPER + SHIFT + Return` shows or hides a kitty terminal (class
`kitty-dropterm`) managed by Pyprland's `scratchpads` plugin. It starts on first
use and is then kept alive, so the shell session and its state survive between
toggles. It floats over whichever workspace is active without retiling the other
windows.

- configuration: `~/.config/pypr/config.toml`, generated by `modules/home/pyprland.nix`
- daemon: `pyprland.service` user unit, bound to `hyprland-session.target`
  (not started under Plasma)
- troubleshooting: `systemctl --user status pyprland`, `journalctl --user -u pyprland`

## Cheatsheet

`SUPER + ALT + &` shows or hides the cheatsheet (shortcuts, commands, what's new),
rendered by `glow` in a second Pyprland scratchpad (`q` closes it). Its source
is `dotfiles/cheatsheet.md` (in French): update it in the same commit as a new
shortcut or tool, and summarise the changes under "Nouveautés".

When that file changes, a Caelestia notification is shown once, at the next
session start (`cheatsheet-notify` user service). The last seen version is
stored in `~/.local/state/nixos-cheatsheet/seen`; deleting it replays the
notification.

## Docs and ChatGPT (Pyprland)

`SUPER + ALT + é` shows or hides the repository documentation, `SUPER + C` ChatGPT.
Both are floating, workspace-independent Chromium app windows (`--app`) managed
by Pyprland (classes `chrome-127.0.0.1__-Default` and `chrome-chatgpt.com__-Default`,
matched by class because Chromium shares one process per profile and derives
the app_id from the URL itself).

- **Docs**: the `docs-scratchpad` script (`modules/home/pyprland.nix`) runs `mkdocs serve`
  on `127.0.0.1:8765` (`pkgs/mkdocs-env` environment, shared with the
  devShell), waits for the port, then opens the window. An `flock`
  lock prevents duplicates; closing the window stops the server. Edits under
  `docs/` live-reload. Startup failure: notification plus
  `~/.local/state/pypr-docs/mkdocs.log`. The repository must live at
  `~/Documents/nix-configuration`.
- **ChatGPT**: nixpkgs has no Linux app (the `chatgpt` attribute is the macOS
  app and does not evaluate on Linux), so the web app runs in a dedicated
  Chromium profile (`~/.local/state/pypr-chatgpt`) that keeps the session. Log
  in once; hiding the window keeps it running, closing it and pressing `SUPER + C`
  again relaunches it.

## Bound helper scripts

`mute-discord` (`SUPER + ;`) and `satty-shot` (`CTRL + Print`) are installed as commands by
`modules/home/hyprland/scripts.nix` (sources in `scripts/`), with their dependencies.

## Validation

The syntax of the three Lua files is checked by the `hyprland-lua` check (run in CI):

```sh
nix build .#checks.x86_64-linux.hyprland-lua
```

After activating a change:

```sh
hyprctl reload full-reset
hyprctl configerrors
```

Then verify monitors, workspace assignments, key bindings, and the wallpaper.

On the desktop, GameMode hooks use `hyprctl eval` to apply the lightweight Lua
profile in one operation. They explicitly select a valid instance instead of
depending on the environment inherited by `gamemoded`. On exit, `hyprctl
reload` restores this declarative file. A missing instance is logged and does
not prevent Syncthing or Docker handling.
